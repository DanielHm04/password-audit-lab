Overview & verdict

start here

CrackLab turns captured hashes into plaintext, and turns that plaintext into findings — a domain password audit a client actually pays for. It is built around one idea: cracking is a supporting step, and the operator's judgment (what to attack, what to not attack, when to stop) matters more than raw GPU horsepower.

The honest verdict

Three parallel research agents pressure-tested this against real professional practice. The finding: the software is professional-track — it independently reinvented ~70% of TrustedSec's hate_crack and the useful half of PACK. The 8 GB laptop GPU is the only "toy" part, and that's fine — pros don't lean on a local GPU anyway.

Adequate for the fast modes that dominate real internal engagements. Hopeless on slow hashes — where the pro move is to relay / pass-the-hash, or rent cloud GPU, and not crack locally.

Tractable here vs. punt to cloud
  • FAST  NTLM · NetNTLMv2 · Kerberoast · AS-REP — crack the weak/medium corporate passwords that are most real wins.
  • SLOW  bcrypt · sha512crypt · DPAPI · LUKS · modern KeePass — don't crack locally; relay / PtH, or burst to an H100.
ScopeThis rig is a training tool for authorized targets only — your HTB lab, the CPTS exam, or a sanctioned engagement. A scope gate refuses every job that isn't declared authorized. Copyrighted lab content and client plaintext never leave the box.

Architecture

3 layers + core

Three layers, cleanly separated. Muscle does the work, Brain decides, Interface is what you touch. Underneath, a Deterministic core can run every capability headless — no LLM, no internet.

Deterministic core — cracklab.pythe floor that always works

Identify · extract · triage · forge · estimate · climb the ladder · report · learn — every one runs offline with zero Brain. The skills orchestrate the core; they never own logic the core can't also run.

Why native Windows

The GPU only runs at full speed natively. A VM can't touch the 3080 without PCI passthrough — so Windows owns the card and Kali is the client over SSH.

Why pluggable Brain

Intelligence isn't welded to one LLM. One adapter seam swaps claude-code for a keyed API or a local Ollama model later — no refactor. ADR-0002.

Why a deterministic core

Cracking must never depend on an LLM being reachable. The core self-orchestrates the mechanical ladder with no Brain at all.

Stops early, always

The climb halts the instant every hash is cracked — you rarely reach the expensive rungs. Each rung is capped by the remaining wall-clock budget.

Slow hashes auto-trim

bcrypt, sha512crypt, DCC2, WPA and friends skip the big rule sets and hybrids entirely — only usernames, targeted, rockyou, and the tiny clem9669-small run. No feedback pass on slow modes.

05

The learning loop

RuleGen · strange-loop

Every win rewrites the ruleset the next run climbs with. CrackLab reverse-engineers each cracked password into the hashcat rule that made it, ranks by frequency, and writes learned.rule — injected as an early ladder rung. Outputs at one level become inputs at a higher level.

Deterministic, no LLM

Rule derivation is pure Python. The loop runs headless and offline, and is reproducible — the same cracks always mine the same rules.

Governed by design

Never learns from a single datum (freq ≥ 2), caps 200 rules/run, regenerates from scratch each job — it can't grow unbounded or drift. ADR-0003.

Scope-isolated

Training scopes feed the shared ruleset; engagement scopes learn into an isolated file with the example plaintext redacted — client structure never leaks.

This is the design pattern from Hofstadter's Gödel, Escher, Bach made concrete: a self-modifying system with a governance gate that stops it from running away.

06

Governance & safety

non-negotiable

The guardrails are the point. They mirror real engagement discipline — and they're enforced by the core, not left to the operator's memory.

gate Scope, first & always

Every crack requires --scope htb|cpts|lab|engagement. No scope, no job — the core refuses. There is no clever way past it.

cap 30-minute wall-clock

Auto mode is time-boxed by default. Extend deliberately (--cap 3600); each rung gets only the remaining budget.

gate Brute-force is opt-in

Mask and PRINCE never run unattended. Auto stops at the last dictionary rung and recommends brute-force as a human decision.

guard GPU thermal abort

Every rung carries --hwmon-temp-abort (default 90 °C) — a laptop card can't cook itself on a long run.

iso Per-engagement isolation

Each engagement:label gets its own potfile and learned ruleset. Client A's plaintext never contaminates client B's stats.

iso Redaction & survival

Engagement scopes auto-redact plaintext from the trophy log. Long jobs run --detach and survive an SSH drop; reconnect and check status.

08

Abuse-not-crack

tier 3 · no GPU

The most valuable credential material often needs no cracking at all. triage keeps the GPU honest, and Kali-side helpers recover secrets by decryption or read.

triage verdicts
  • abuse machine accounts ($) — ~random 120-char → pass-the-hash, never crack
  • abuse krbtgt — golden-ticket material, never crack
  • flag blank NT hash — already a critical finding
  • flag reused hashes — crack once, applies to all
  • note AES-only Kerberos — slow; request an RC4 downgrade
Kali helper scripts (kali\)
  • dpapi-harvest.sh — browser / RDP / Wi-Fi / vault creds via the domain backup key (DonPAPI · hekatomb)
  • gpp-decrypt.sh — GPP cpassword, reversed with Microsoft's published AES key
  • laps-read.sh — cleartext local-admin passwords with the right ACL
  • capture-cheatsheet.md — the whole capture → hashcat handoff

These live on Kali by design — impacket, netexec and DonPAPI belong on the capture host, not the cracking rig. CrackLab's job is the GPU and the deliverable.

10

Design decisions

docs\adr

ADR-0001

Claude Code as Brain, no API. The terminal session is the operator — no monolithic app welding an LLM into the cracking logic, no API cost.

ADR-0002

Pluggable Brain + offline core. Intelligence sits behind one adapter seam; the deterministic core cracks with no LLM reachable.

ADR-0003

Self-modifying learned rules. The strange-loop, with a governance gate against runaway growth, drift, overfitting, and cross-client leakage.

Deliberately skipped
  • Hashtopolis — no cluster (single node)
  • Web GUIs (CrackerJack / Mentalist) — headless by design
  • rockyou2021/2024 giant dumps — bad hits-per-GB
  • PassGAN / ML candidate-gen — debunked; a best64 ruleset beats it
Escape hatch / deferred
  • Cloud burst (vast.ai / NPK) — rent an H100 for the one slow-hash job that needs it
  • api / ollama Brain backends — seams ready
  • Parallel multi-hash jobs

Got a hash, don't know the type
python core\cracklab.py identify h.txt

Got an NTDS dump + some OSINT
python core\cracklab.py triage ntds.txt --out c.txt

python core\cracklab.py auto c.txt --scope cpts --username --targeted w.txt
python core\cracklab.py report c.txt --mode 1000 --username
